# 몬스터 스킬 네이티브 그림체·픽셀 검증

## 기존 문제 원인

- AI가 큰 해상도로 다시 그린 캐릭터를 축소했기 때문에 원본과 갑옷 실루엣, 선 굵기, 픽셀 밀도가 달라졌다.
- 팔레트만 원본 색으로 바꿔도 형태와 픽셀 배치는 복구되지 않았다.

## 수정 방식

- AI 생성 캐릭터 몸체를 최종 출력에서 완전히 제거했다.
- Sword Queen, Axe King, Bow/Lance Bishop, Shield Rook의 실제 인게임 모션 PNG를 사용했다.
- 원본 이미지는 확대, 축소, 회전, 색상 변환 없이 `native_scale: 1`로 배치했다.
- 스킬별 검기, 화살, 속도선, 충격 효과만 원본 팔레트의 1px/2px 선으로 추가했다.
- 효과를 먼저 그리고 원본 캐릭터를 마지막에 복사해 캐릭터 픽셀이 효과에 덮이지 않게 했다.

## 정지 이미지 분석 1차 — 크기와 격자

- 135개 프레임 모두 160×112 캔버스다.
- 모든 원본 캐릭터의 배율 값은 1이다.
- 보간, 안티앨리어싱, 리사이즈가 없다.

## 정지 이미지 분석 2차 — RGBA 픽셀 완전 일치

- 실제 원본 캐릭터의 불투명 RGBA 픽셀 160,447개를 출력 프레임과 좌표별로 대조했다.
- 불일치 프레임: 0개.
- 불일치 픽셀: 0개.
- 근거: `hys_NativePixelExactValidation.json`.

## 정지 이미지 분석 3차 — 전체 프레임 육안 비교

- `hys_NativeStyle_15_AllFrames.png`에서 15개×9프레임을 원본 크기로 확인했다.
- 갑옷, 얼굴, 체형, 무기, 외곽선, 픽셀 크기가 스킬 사이에서 변하지 않는다.
- 잘림과 캔버스 경계 접촉이 없다.

## GIF 분석 1차 — 디코딩과 재생

- GIF 15개, 각 9프레임, 640×448, 90ms를 전수 디코딩했다.
- 누락과 손상 프레임이 없다.

## GIF 분석 2차 — 이동과 복귀

- 15개 GIF의 중심 이동량, 최소 여백, 시작/종료 복귀 위치를 검사했다.
- 경계 잘림 0개, 비정상 중심 순간이동 0개.
- 준비 → 실행 → 충격 → 복귀 순서를 유지한다.

## GIF 분석 3차 — 중복과 Unity 연결

- 135개 프레임은 모두 고유하다.
- 15개 AnimationClip의 9개 GUID 순서가 실제 PNG 메타와 일치한다.
- Pass13, Pass14, Pass15 전체 검증이 통과했다.
